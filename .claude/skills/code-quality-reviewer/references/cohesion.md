# 응집도 (Cohesion)

## 정의 및 유형

응집도는 모듈 내 요소들이 얼마나 밀접하게 관련되어 있는지를 측정합니다.

| 유형                         | 설명                               | 품질      | 이 프로젝트 예시                                  |
| ---------------------------- | ---------------------------------- | --------- | ------------------------------------------------- |
| **기능적 (Functional)**      | 모든 요소가 단일 기능 수행에 기여  | 최상      | `src/utils/posts/url.ts` - URL 생성만             |
| **순차적 (Sequential)**      | 한 요소의 출력이 다음 요소의 입력  | 우수      | 파이프라인 패턴 (현재 없음)                       |
| **통신적 (Communicational)** | 같은 데이터를 다루는 요소들        | 양호      | `src/utils/posts/query.ts` - CollectionEntry 다룸 |
| **절차적 (Procedural)**      | 특정 순서로 실행되어야 하는 요소들 | 보통      | 초기화 시퀀스 (현재 없음)                         |
| **시간적 (Temporal)**        | 같은 시점에 실행되는 요소들        | 낮음      | `astro:page-load` 핸들러들 (주의 필요)            |
| **논리적 (Logical)**         | 논리적으로 분류된 요소들           | 매우 낮음 | 발생 시 분리 필요                                 |
| **우연적 (Coincidental)**    | 무관한 요소들의 모음               | 최악      | `utils/helpers.ts` (만들지 말 것)                 |

## 측정 가능한 응집도 기준

### 유틸리티 파일

| 신호                    | 기준     | 조치                  |
| ----------------------- | -------- | --------------------- |
| export 개수             | 8개 초과 | 분리 검토             |
| 파일명과 무관한 함수    | 1개 이상 | 이동 또는 파일명 변경 |
| 상호 호출 없는 함수들   | 50% 이상 | 응집도 재검토         |
| import하는 외부 모듈 수 | 6개 초과 | 책임 과다 의심        |

```
GOOD: src/utils/posts/url.ts
- getPostUrl, getSeriesUrl, getPostSlug (3개)
- 모두 "URL 생성" 목적
- 상호 의존: getPostUrl → stripLangFromId 호출

GOOD: src/utils/filter.ts
- isPublished 단일 함수
- 극도로 응집됨

WARNING SIGNAL: 가상의 utils/content.ts
- getPostUrl, formatDate, isPublished, sortPosts, translateText
- 5개 함수가 서로 다른 관심사 → 분리 필요
```

### Astro 컴포넌트

| 신호                   | 기준      | 조치                    |
| ---------------------- | --------- | ----------------------- |
| 프론트매터 줄 수       | 80줄 초과 | 로직 추출 검토          |
| 데이터 페칭 호출 수    | 3회 초과  | 별도 데이터 레이어 고려 |
| 내부 헬퍼 함수 수      | 4개 초과  | 유틸리티로 추출         |
| Props + 내부 상태 합계 | 10개 초과 | 컴포넌트 분리 검토      |

```
GOOD: PostNavigation.astro (프론트매터 12줄)
- Props 받아서 렌더링만
- 데이터 페칭 없음

ACCEPTABLE: SeriesListView.astro (프론트매터 ~55줄)
- 데이터 페칭 + 그룹화 + 정렬 + 렌더링
- 뷰 컴포넌트로서 허용 범위

WARNING: 가상의 DashboardView.astro (프론트매터 120줄)
- 3개 컬렉션 페칭 + 복잡한 변환 + 8개 헬퍼 함수
- 분리 필요
```

## 응집도 체크리스트

**파일 레벨:**

- [ ] 파일명으로 모든 export를 예측할 수 있는가?
- [ ] export 개수가 8개 이하인가?
- [ ] 새 함수 추가 시 "이 파일이 맞다"고 확신할 수 있는가?

**함수 레벨:**

- [ ] 함수들이 같은 데이터 타입을 입출력하는가?
- [ ] 함수들이 서로를 호출하는 관계가 있는가?
